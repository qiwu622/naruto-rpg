# Agent 叙事检查改为软建议（v3.5.2）

## 问题与原因

截图中的 `Writing outline omits CharacterDecision ids` 来自详纲规范化函数：它把每个角色代理的内部编号都当成必须引用的字段，遗漏任意一个就抛异常，正文作家因此没有机会执行。

同一条链路还存在多处叙事门槛：要求每个角色素材都演出、禁止作家补充 NPC 行动、把模型审核的 `approved:false` 当成失败、按审核结果反复生成大纲、在提交时因文本与角色私有想法重合而撤销回合。角色代理失败时还会自动编造“保持姿态等待”的动作。这些机制把可讨论的写作建议变成了流程阻断和机械叙事。

## 新行为

- 角色引用、出场覆盖、连续性和预设审核结果只形成内部建议，不阻断正文，也不自动触发大纲重写。
- 角色素材按需选用，作家可以按已有设定补充合理人物、行动、台词和反应；不合理的玩家诉求通过故事内的尝试、阻力或后果处理。
- 详纲缺少边界或停止点时补充通用建议；格式不可用或服务失败时使用已有场景规划，不生成虚假的故事结果。
- 单个角色代理不可用时跳过该素材，其他角色继续执行；不再编造原地等待的兜底动作或相应记忆。
- 详纲字数估计不再被截断到 2000，最终文风、篇幅与格式仍继承玩家主预设。
- 代理建议只进入写作上下文与诊断面板；正文流仍只接收最终作家的输出。进度名称改为“详纲建议”“整理建议”，删除已不执行的强制修订步骤。
- 更新流水线修订号，旧版阶段缓存不再复用。

取消操作、空正文/详纲误作正文、变量结构和原子提交失败仍按实际执行错误处理。NPC 私有字段在进入作家上下文前继续过滤；单纯的文本重合提示不再否决回合。
