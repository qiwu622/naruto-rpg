# 轻量续玩副本

已在本地实现，尚未发布。网页与 Android 使用相同个人存档代码；Android 仍沿用已有本地存档能力，不新增云端登录或发布安装包。

## 玩家行为

- 个人存档页可从当前游戏或某份已保存的个人档生成副本。默认保留最近 50 回合，可输入其他正整数。
- 保存位置是副本终点；沿该位置的父链取近期回合，包含同回合的 IF 起点。不会采纳分支的后续 head 或其他 IF 线。
- 当前游戏先完整保存到独立存档库；提交失败则停止。已有原档只读。新副本以独立条目保存，不自动读取，不删除原档。
- 每个保留节点的正文、日报、插图引用、完整变量、各层记忆和关系都保留该节点当时的值。不会把终点记忆回填到较早节点，也不调用模型重新摘要。
- 副本采用独立主线，可继续生成回合、回退及创建新 IF 线。老正文、老回退点与未选线路需读取原档。
- 原档与副本共同占用本地空间；要腾出空间，玩家需先导出原档，再自行管理原档。

## 数据与兼容

- 继续使用 `naruto.save-package/v1` 和时间线 2.0；新增来源和保留范围位于 `meta.value.continuation`，不另造不兼容的导出格式。
- 保留节点 ID、实际回合号及历史事件来源。节点父子关系、depth 和运行时主线绑定重建；新根的 continuity delta 包含已保存的历史事件，使其无需被裁去的节点也能恢复事实。
- 保留当前节点自身的完整 `_memory`、`_continuity`、关系与任务状态。已有旧档仍由原迁移器读取。联机个人导出的 non-Agent sidecar 保持在顶层，不写进模型可见状态。
- 聊天上下文由所保留回合的 delta 重建；旧版完整聊天缓存不随每个节点重复携带，候选选项仍走正文事实投影。
- 本地目录记录 `continuation` 范围；云端预览记录范围。导入、读取后再次保存、继续游戏后的默认云档均保留轻量身份，终点按当前保存位置更新。
- 完整导出每批最多同时解压 8 个节点；存档包嵌套 payload 也按节点序列化。仍需持有完整逻辑存档；不将这一改动描述为全程常量内存。

## 验证

- `node scripts/continuation-save-regression.mjs`：原档不变、IF 隔离、旧位置不读取未来、按回合去重计数、完整记忆/日报、JSON/gzip、旧结构兼容及失败停止。
- `node scripts/continuation-save-browser-regression.mjs`：真实 IndexedDB、界面生成与取消、桌面与移动视口、文件下载导入、临时云端 API、读取/回退/续玩/新 IF、磁盘配额异常回滚。只使用临时测试数据，无模型调用。
- 旧存档库、IF 管理、云端管理和 Android 回归继续运行。

## 后续底层优化

本次不把轻量副本当作完整档去重的替代品。跨存档内容共享、状态差量与定期完整检查点、后台分块加载、云端块级增量仍需独立的数据格式迁移和恢复验证；当前普通完整档保持原有完整历史语义。
