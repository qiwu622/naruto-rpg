# ADR 0007：全新联机档由服务端自动生成开场

- 状态：已接受
- 日期：2026-08-29

## 背景

全新联机档原先在双方确认开局后先进入付款选择等待，再要求玩家提交普通行动。凭证或模型投影未及时物化时，界面会长期停在“正在同步”；即使同步完成，玩家填写的开局资料也没有直接触发第一回合正文与权威变量初始化。

## 决策

`new_multiplayer_save` 的双方必须先确认同一联机凭证策略，策略所需席位必须绑定精确 active profile。确认过程不调用模型做能力探测。第二名成员确认开局后，服务端创建 `turn_kind = OPENING` 的第 1 回合，为 A、B 各封存一份幂等的服务端开场锚点，自动物化付款策略、建立计费计划与授权，并进入现有 Resolution → Writer → Continuity → 原子提交链。

开局草稿只进入可信 `opening_context`。开场锚点只绑定结构化 outcome，不代表玩家说话、移动、消费、决定或内心活动；模型必须在可交还首次玩家选择的位置停止。浏览器不调用单人 `MessagePipeline`，也不能在 `OPENING` 回合提交玩家行动。

升级时，只有全新联机档中直接基于 genesis、回合号为 1 且尚无任何行动提交的旧回合可以迁移为 `OPENING`；已有玩家行动的回合保持 `ACTION`。

## 后果

- 填写并确认开局即直接开始生成第一回合，同时初始化角色、世界、资源、地图、时间和记忆等权威状态。
- profile 绑定或双方策略确认缺失时，开局按钮明确阻断并引导完成联机 AI 设置，不再伪装成后台同步。
- 开场仍使用双方确认的 BYOK 策略、相同计费审计、修复机制和最终原子提交保证。
- 开场提交记录不能获得玩家行动的披露语义；开场提交完成后才开启普通 `ACTION` 回合。
