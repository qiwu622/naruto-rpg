# ADR 0004：联机档使用 Room/Epoch/Checkpoint 谱系

- 状态：已接受
- 日期：2026-08-22

## 背景

联机房间既可以从来源玩家的明确单机节点派生，也可以建立全新的联机世界。已有档派生房还允许双方按各自受众权限导出单机副本，并允许来源所有者以后从选定的最新来源分支建立新联机时期。把这些操作理解成覆盖同一份存档或自动合并两个世界，会造成日期、任务、角色私密状态和时间线无法确定地合并。

## 决策

`Room` 是稳定联机容器，`RoomEpoch` 是从一个明确基点开始的连续分支，`RoomCheckpoint` 是 genesis C0 或已提交回合后的不可变检查点。创建新 epoch、归档恢复和个人导出均只新增谱系节点，不修改旧 epoch、checkpoint 或原单机分支。

`existing_save_derived` 只导入来源所有者的世界和客方兼容角色，不合并客方原世界。两名原成员都可获得按自身权限生成的个人单机副本；只有不可变的 `origin_owner_user_id` 可以把最新来源单机档回灌原 Room。再次从来源档建立 epoch 时必须验证两个签名 `RoomActorBinding` 构成唯一双射，先执行版本化隐私规范化，再只做控制权重绑。

`new_multiplayer_save` 只能归档后从联机 checkpoint 续接，不提供可玩单机导出或最新来源档回灌。

## 后果

- `origin_type`、旧 epoch 与旧 checkpoint 永不被续接操作覆盖。
- 所有谱系、导入 diff、导出和续接 API 都必须先按请求成员投影。
- 客方私密信息不能从来源所有者的单机文件重新构造；无法安全剥离时拒绝整个导入。
- 多人转单机必须通过版本化 codec，并确保另一成员的 sidecar 永不注入单机 Agent。
