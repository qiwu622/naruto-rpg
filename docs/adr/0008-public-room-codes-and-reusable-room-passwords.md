# ADR 0008：公开房间号与内部 ID 分离，加入凭证采用房间密码

- 状态：已接受
- 日期：2026-08-29

## 背景

早期联机实现把玩家填写的房间号直接作为 `room_id` 主键，并把所谓“邀请码”建模为全服唯一、一次性且会过期的 token。结果是历史归档房间永久占用房间号，不同房间不能设置相同密码，成功加入后密码还会被消费；这些行为与玩家理解的“房间号 + 房间密码”不一致。

## 决策

`multiplayer_rooms.room_id` 继续作为不可变的服务端权威主键，所有成员、纪元、回合、检查点和事件只引用该内部 ID。新增公开 `room_code`，创建、分享、首次加入和恢复入口可以使用它；数据库仅对 `lifecycle != 'ARCHIVED'` 的房间施加部分唯一约束。房间归档后释放公开房间号，但不会改写任何旧谱系引用。

兼容命名的 `room_invites` 表只保存房间密码哈希。唯一性改为 `(room_id, token_hash)`，加入查询必须同时绑定解析后的内部房间 ID 与密码哈希。成功加入不增加使用次数，也不检查旧的次数或过期字段；撤销、房间归档和固定双席位仍是有效的安全门禁。旧字段只为无损迁移保留，不再承载密码语义。

房间号和密码只做去除首尾空白及非空校验；房间号统一为大写以保持原有大小写不敏感体验，密码保留大小写和字符内容。自动生成值仍使用易读短码，但自定义值不再限制长度、首字符或字符集合。

## 后果

- 不同当前房间可以使用相同密码，密码不会在第一次成功加入后失效。
- 当前房间的公开房间号仍不能碰撞；归档后可由新房间立即复用。
- 创建响应和成员房间投影同时返回 `room_id` 与 `room_code`。浏览器分享 `room_code`，加入后切换为内部 `room_id` 访问 SSE、回合和谱系接口。
- 旧数据库升级时以原 `room_id` 回填 `room_code`，因此既有链接与已保存会话保持可恢复。
