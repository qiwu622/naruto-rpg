# 可配置历史数量与大档续玩副本

日期：2026-10-11。接续 [大档启动与救援](large-save-rescue-2026-10-11.md)。本轮仅修改、测试和同步本地 public 文件；未部署、推送或发布安卓安装包。

## 玩家可见行为

- 玩家设置 → 玩法 → 存档与空间 → 每页历史回合数：默认 100，可填写任意正整数。主线与 IF 线分别分页，使用“更早 / 较新”查看完整旧历史。改小数量不会删除节点、裁剪记忆或扩大/缩小模型上下文。刷新及读取旧档后沿用本机设置。
- 存档库生成续玩副本、独立救援页的保留回合数均默认 100，可自行填写。取消救援页原来的固定选项及后台 200 回合上限；超出实际可用数量时保留所选路线的全部祖先回合。同一回合的 IF 起点不多占一个回合名额。
- 续玩副本只包含所选线路和时点，每个回退点保留自身的正文、变量、关系、记忆、日报和媒体引用。完整旧回合及其他 IF 线仍在原档中。

历史浏览沿用原有行为：翻页不改变游玩位置；点击历史回合会恢复到该回合，后续节点仍保留，从历史位置继续输入可产生 IF 线。显式“逆转时间至此”的确认/剪枝行为未改变。

## 存储实现

原档存储的续玩提取现在只保留节点 ID/回合目录，Worker 逐条读取、转换、压缩和写入副本，不再组装整份副本并跨线程复制。最近 20 个节点保留热状态，其余副本节点压缩；这个内部窗口与玩家设置的历史分页数量独立。

副本写入期间标记为未完成，不出现在可读取存档列表。全部节点写入且记录数校验通过后，才提交完成标记。取消、空间不足、最后提交失败均清理本次半成品，原档及当前工作档不变。救援切换仍使用原有的原档备份与切换事务。

真实无头 Chromium / IndexedDB，使用合成档，没有调用付费模型。

- `history-window-regression.mjs`：390 节点、两条线路；默认 100、自定义 37/300、较早页、压缩旧正文实际显示、返回最新回合、设置不改变 AI 聊天历史、无效输入、刷新与状态恢复后偏好保留、全部原节点保留；320/390/768 px 输入框不溢出；主线程无完整节点表读取。
- `incremental-continuation-regression.mjs`：391 个原始节点（含同回合 IF 起点）；保留 100/225/9999 分别得到 100/225/260 个可用回合。逐回合状态、父子关系、正文、日报、媒体、聊天及记忆增量与既有转换语义一致，gzip 导出校验通过。

- `timeline-recovery-regression.mjs`：原始记录保留、取消/空间不足回滚、目录写入失败、并发导出保护、IF 隔离、读取原档、损坏最新回合后选择较早回合救援、移动端独立页面通过。

## 边界

未拿到玩家实际损坏原档，未做安卓真机验收。旧版整包文件导入/合并仍可能需要较大内存；状态检查点/增量及跨回合去重尚未实施。浏览数量设置很大时，单页 DOM 也会增加。

页面/浏览器被强制结束时，未完成副本可能留下不可见的临时记录，原档不会因提取被修改；自动回收这类中断残留尚未加入。向量记忆继续保持可选、默认关闭，未改变此前实现。
