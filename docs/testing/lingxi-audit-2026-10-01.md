# 灵希模块检查与修复（2026-10-01）

本次检查本地当前工作区，覆盖灵希控制器、工具执行与降级、提案适配器、会话存储及浮窗交互。保留工作区中其他任务的修改；未部署网站、推送 GitHub 或更新安卓安装包。

## 已复现并修复

| 问题 | 原因与复现 | 修复 |
| --- | --- | --- |
| 回复期间切档后，旧请求能修改新档 | 工具在执行时读取当前状态，提案只绑定创建时的状态，没有绑定用户发送消息时的存档。延迟模型工具调用，再切换节点，旧版仍会自动写入。 | 请求绑定节点与分支，在工具调用、异步提案完成、回复返回时核对；读档、重置和分支切换使旧请求失效，清理该轮未确认提案。同节点 ID 的导入也会终止旧请求。 |
| 兼容降级丢失工具结果、可能重复操作，说明与实际写入矛盾 | 原生工具执行后抛错，备用文本协议重新从原始消息开始；文本协议失败后普通对话也丢弃执行记录。测试中同一写入执行了两次；实际写入成功后仍显示“没有修改设置或存档”。 | 同一请求保留有长度上限的执行记录；跨协议重复的同名、同参数操作复用已有结果，失败操作也不盲目重复。只读工具可以重新读取；同一协议内的连续操作和新请求不受去重影响。降级提示依据实际工具调用区分。 |
| 浮窗重新挂载后不更新 | 断开时取消订阅，却没有重置连接标记；取消动画帧后也保留旧帧 ID。移除并重新添加浮窗后，消息与提案不再刷新。 | DOM 事件只绑定一次，每次挂载恢复订阅和界面状态，卸载时清空连接与动画帧状态。 |
| 中文输入法回车选字时误发消息 | Enter 处理没有排除正在组合的输入。带 `isComposing=true` 的按键会直接发送并清空输入框。 | 组合输入以及兼容的 229 键码不触发发送；选字完成后普通 Enter 仍正常发送。 |
