# 战术回合战斗 · 本地验收

日期：2026-10-03。沿用当前工作区其他更新；未部署正式站、测试站、GitHub 或安卓安装包，未使用付费模型。

## 使用入口

设置 → 玩法 →「战术回合战斗」。默认关闭，关闭时保留原叙事战斗；已有开启战术面板的存档会使用新回合规则。此次适用于个人模式，联机仍由服务器结算。

实际发生遭遇时，模型可登记战斗并停在玩家第一次选择处。对正文中明确在场的人物输入“我向某某发起攻击”，可直接创建本地战斗回合。邀请切磋、询问、引述他人言语、过去或假设的战斗不自动扣血；疑义交给正常叙事流程。

选招会填入主输入框，可以补写战术细节；卡片确认和主发送按钮走同一路径。修改为“不使用 A，而是使用 B”会以 B 为准。未识别为已学招式的自由声明按走位、地形或制造先机处理，不凭空创建新技能。

快捷栏最多 4 个招式，可固定、取消或替换；按存档根 ID 保存本机偏好，不写战斗变量。全部招式与适用忍具仍可打开使用。

## 本轮规则

- 忍术输出参考查克拉上限、精神力上限、忍术造诣与招式熟练度；剩余查克拉用于支付消耗。体术主要使用体力，幻术主要使用精神力。
- 攻防与威力形成基础伤害，命中、先制、速度、暴击、小幅伤害浮动及状态分别结算。熟练度不重复乘算，旧显式威力按原值读取。
- 防御、观察、佯攻、自由战术、撤离、替身、分身、屏障、医疗、灼伤、束缚与幻术状态均有有限回合规则。资源不足仍可尝试，但概率或效果降低；无物品数量则不能凭空使用忍具。
- 五行相克作用于实际屏障，不把 NPC 的查克拉属性直接当成身体弱点。远距离近战先接近，本轮不凭空造成伤害。
- NPC 存在后台能力卡，不等于玩家已知精确数值。未知敌情显示区间或未探明，预览不会泄露后台精确数据。
- 本地计划在生成正文前完成，但正文、资源、战报与记忆一起持久化。失败回滚；同一来源和行动的重试沿用判定，不重复扣费。
- 生命归零表示战术失能，不直接触发死亡；恢复后清理失能标记，不影响后续独立伤势判定。
- 单次模型调用仍只有一次请求；已结算的战斗资源无需重复标签，其他变量领域、记忆和日报仍按原契约处理。

## 验证命令

```text
npm run test:tactical-combat
npm run test:tactical-combat-ui
node scripts/pipeline-state-epoch-regression.mjs
NODE_ENV=test npm test
```

浏览器回归在 Windows Node / Chromium 执行；主回归在 WSL 执行。模型全部为固定本地响应，外部请求禁止。

覆盖：概率分布与同种子重现、技能/背包兼容、状态过期、资源不足、误触发开战、模型重复扣费、失败回滚、切档取消、旧模式、单次调用；实际 App + AppShell 三回合提交与 IndexedDB 读回；360px 布局、键盘操作、44px 控件、自定义快捷栏及换档隔离。

5,000 个确定种子样本：目标命中 90%，实测 89.90%；命中后 20% 灼伤，整体目标 18%，实测 18.18%。统计测试不使用真实模型。

图片：`reports/tactical-combat/battle-desktop.png`、`battle-mobile.png`、`battle-finished-mobile.png`。

实际结果：战斗核心 23 组、开战识别 7 组、会话保护 10 组、流水线集成 8 组通过；界面 6 组及实际主界面三回合 3 组通过。切档保护 Node 14 组、真实 Chromium/IndexedDB 8 组通过。完整 `NODE_ENV=test npm test` 退出码 0，227 个 source/public 文件一致，`git diff --check` 通过。

## 当前边界

这是首版单对手战术引擎，未实现多角色站位或区域随机遭遇调度。技能从现有条目和通用效果映射读取，尚未逐一手写所有血继与复合忍术的专属机制。已验证浏览器窄屏，未声称完成真实安卓设备或真实模型的文风验收。
