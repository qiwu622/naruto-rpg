# 大存档本地导入修复验证

## 原因与修复

`decodeTimelineSaveFile()` 默认将解压后的文件限制为 200 MiB。网页存档库、旧档导入、安卓共用界面和存档库再次读取都经过这个解码器，因此应用自己导出的完整大档也会被拒绝。

修复取消默认的本地文件容量上限；明确传入 `maxDecompressedBytes` 的调用仍逐块计数并在超限时停止。格式、gzip、UTF-8、存档包 SHA-256、分区、谱系与时间线状态校验继续生效。云端配额仍由云存档 API 管理。存档库新增读取/解压及校验/保存状态提示。

## 复现与回归

- 原代码用 201 MiB 压缩数据连续两次复现“存档解压后超过 200 MiB 上限，已停止导入”。仅为同一文件显式放宽解码上限后，其全部内容均能读出，确认错误来自默认上限。
- 新回归在修复前通过实际存档库文件输入框导入 **209.05 MiB、201 个节点、主线及一条 IF 线**的有效签名 gzip 存档，稳定失败于同一错误。
- 修复后，同一签名 gzip 与旧格式普通 JSON 都成功导入真实浏览器 IndexedDB，并能再次读取、通过完整性校验。逐节点检查正文的长度、中文/emoji/转义字符及首尾内容，检查日报、记忆、连续性账本和两条线路；已有旧档及当前游戏位置不变。
- 同一内容的不同文件格式按原规则去重；损坏的包校验值、损坏 gzip 和显式指定的容量限制仍拒绝导入，不改变既有存档。
- 测试文件在临时目录生成并自动删除，使用隔离浏览器数据；没有模型调用，没有读写玩家数据。
