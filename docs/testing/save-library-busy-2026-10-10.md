# 存档库首次保存误报忙碌 · 2026-10-10

## 反馈与复现

玩家反馈刷新后，存档库第一次点击保存就提示“正文正在生成或存档正在切换，请等待完成后再操作”，但没有生成正文。

通过真实浏览器、IndexedDB、应用事件入口和真实 MessagePipeline 初始化后刷新恢复进度，在导出边界暂停任务以模拟大档读取，连续点击存档库入口再首次保存，连续两次稳定复现原提示。记录为 `pipeline.isProcessing=false`、`_saveTransition=true`。

原因是 `app:open-saves` 每次打开面板前都会隐式捕获完整原档。第一项隐藏备份未完成时，第二次入口点击跳过备份并打开面板，面板自身显示为可操作，但应用保存锁仍被隐藏备份持有。大档保存耗时使窗口扩大；统一错误文案又让玩家误以为正文在生成。

## 修复

- 打开存档库仅刷新账号上下文和读取目录，不再隐式备份或占用存档操作锁。
- 保存当前档、生成续玩副本、读取、开新档及 IF 操作原有的显式备份、事务和并发保护保留。
- 将生成正文/更新变量和正在保存/切换存档的提示分开，真实任务进行时仍阻止冲突写入。

## 验证

- `scripts/save-library-busy-regression.mjs`：6 组通过。覆盖刷新后的首次保存、重复点击入口、重开目录、真实生成保护、保存时关闭重开、失败重试、取消开新档；等待的真实导出在放行后完成完整保存。
- `npm run test:save-library`：6 + 13 + 10 + 9 组通过，涵盖个人档、IF、续玩副本、保存失败及旧档保留。
- `scripts/save-library-string-limit-regression.mjs`：已改为应用的 `app:open-saves` 真实入口，不再直接挂载面板。652.01 MiB、393 回合、590 节点/2 分支，保存、读取、近 100 回合副本、导出、开新档、刷新恢复的 6 组全部通过。
- `scripts/save-library-cloud-regression.mjs`：13 组通过。首次执行暴露测试把“面板可操作”误当成“异步云列表已返回”，修正为等待实际云档卡片；未修改云端运行代码。
- `public` 与源码同步，差异格式检查通过。

前一轮大档测试直接挂载组件，未覆盖打开存档库入口的隐式备份，是遗漏此问题的测试缺口。新增回归已加入 `npm run test:save-library`。没有强制清除运行中的锁、跳过备份、修改玩家数据或调用付费模型。
