# v3.6.4 大档救援与客户端内更新验收

日期：2026-10-11。网页与 Android 版本 3.6.4，Android versionCode 30604。

## 变更和兼容

- 大档使用独立时间线目录、按需读取与后台逐条备份/导出；救援前保留完整原始记录，再创建所选恢复点的续玩副本。
- 历史分页和续玩保留回合数可以设置，默认 100。浏览数量不删除原节点，不改变模型上下文。
- 向量记忆默认关闭，开启才请求嵌入；断网回退，缓存不随回合复制。
- Android 更新支持系统后台下载、进度、取消、重新打开后恢复、校验和应用内发起系统安装。安装前检查 SHA-256、长度、包名、版本和现有签名。
- 旧客户端需通过现有下载入口覆盖安装本次版本；之后可在 App 内完成后续更新。安装由用户在安卓系统页面确认，不卸载或清除原 App 数据。

## 回归验证

完整 `npm test` 命令链各段通过。使用 `NODE_ENV=test`；未关闭生产安全校验。遇到的两条旧测试断言已按当前接口修正并从失败点续跑：原始档案的摘要从真实读取结果计算后比较；流式阅读按用户要求断言不强制滚动。保留首轮、续跑及最终日志于 `reports/release-v3.6.4/npm-test*.log`。

专项大档、救援、取消/空间不足回滚、历史分页和可选向量记忆的证据见 [大档救援](large-save-rescue-2026-10-11.md) 与 [历史窗口](history-window-2026-10-11.md)。209 MiB JSON/gzip 导入也在本轮完整命令链中复验通过。没有使用付费模型。

Android 新增更新服务回归 7 组，以及真实 App 入口的浏览器 UI 回归，覆盖下载、后台继续、正文生成时等待保存、权限跳转、取消和离线重试。320/390/768 px 布局通过。

使用专用 Android 15 / API 35 模拟器及最终 APK，非物理手机。APK SHA-256：

`27563beb7ce73bdb684b18fcc422a379c2a9b8bf5a711054ed976a55cbccceea`

- Gradle 构建、原生单元测试、签名及私有文件排除检查通过；253 个 APK 共享资源与当前 public 文件逐一一致。
- 从 3.5.3 覆盖升级至 3.6.4，LocalStorage 标记、6 个时间线节点、主线/IF 和历史记忆保持一致。
- 原生 DownloadManager 实测 3 项通过：系统下载、重新创建控制器后继续读取进度、完整签名校验、取消/重试、错误校验和拦截。
- 真实原生插件打开安装权限页，在系统 UI 同意后进入 PackageInstaller，点击更新并得到系统“App installed”结果。安装后 APK 哈希与构建一致，6 个节点及两条分支保持。
- 原有 Android 设备回归 9 组通过：共享 UI、原生中文流式 HTTP、Agent SDK、gzip/错误响应/重定向凭据隔离、取消请求，以及系统文件选择器真实导出/取消/导入。

未发布 APK 的下载验收由 instrumentation 在模拟器回环地址提供同签名 APK；生产 JS/原生桥没有测试下载地址入口，始终使用官方地址。首次下载测试因专用模拟器遗留失效代理以及 Google 联网探测不可达而超时；清理该临时模拟器网络设置后同一 APK 原生下载测试通过，未修改产品的网络或 TLS 校验。

运行新增原生回归（只允许专用模拟器）：先安装同一次构建的 `native-tests.apk`，执行 `NativeUpdaterTest`；随后运行 `scripts/android-in-app-update-regression.mjs <构建输出目录>`。`NARUTO_ANDROID_ADB` 和 `ANDROID_SERIAL` 指定测试设备。覆盖升级测试为 `scripts/android-upgrade-preservation-regression.mjs <构建输出目录>`，应在旧版本仍安装时运行。

原始证据位于 `reports/android/release-v3.6.4-final/`。性能样本是合成档；未取得玩家实际损坏原档，完整状态增量去重与物理手机极端内存压力仍未验收。
