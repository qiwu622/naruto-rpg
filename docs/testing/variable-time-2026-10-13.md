# 变量自检与时间更新验证（2026-10-13）

本轮为本地修复，没有发布网站、GitHub 或 Android 安装包。此前未发布的存档、记忆与变量改动保留。

## 已复现的执行问题

最关键的问题在自检与指令解析的交界处。模型在自检文字里写“使用 `<variable>` 标签”而没有在自检内闭合这个示例字样时，旧提取器把它与自检之后第一条真实变量的结束标签配对。随后隐私边界过滤丢弃整个重叠块，第一条真实更新也随之消失。

Flash 实测的原始响应已经同时输出时间与查克拉标签，自检、记忆和日报的日期也正确，但执行结果只有查克拉变化。修复后直接回放同一响应，时间与查克拉均正确更新，没有为回放再调用模型。提取器现在先跳过内部自检里的开标签，再匹配真实指令；私密块内部的示例仍不执行，业务 JSON 内嵌私密内容仍被过滤。

其他已复现并修复的问题：

- DSL 接受 `KYYY-MM-DD`，世界面板却读成默认的木叶48年1月1日。两种日期格式现在共用解析器。
- 日期跨年只同步月份，年代停留在旧年。完整日期写入现在同时同步月份、年代，兼容旧 `<var>` 路径。
- `HH:mm` 被读成清晨；现在保留精确时刻，昼夜氛围也识别时钟。
- 深夜进行一次时段推进仍停在深夜；现在正确进入次日。已经在凌晨或00点后时，不额外多跳一天。

沿用项目原有每月30天、每年12个月的剧情历。读取旧档时不改写原日期字符串，旧季节/第几天格式以及已有31日记录仍可读取；本轮不批量迁移历史日期，也不按现实时间自动推进游戏。

## 自检与预设

默认变量预设更新至 v19。自检改为简洁的事实差异摘要，不再要求复写整段玩家输入；仍核对八个领域，但把重点放在“已发生依据、旧值/新值、对应可执行写入”。自检文字和标题仍是软提示，不增加格式拒绝或自动重试条件。

每轮提供独立的当前时间基点，普通更新器、旧自定义预设与 Agent 共用该规则。时间项检查起点、实际经过、最终落点及时间标签；休息后的时间与资源恢复分别记账。正文未发生的未来约定、回忆、梦境和未选选项不推进时间。没有可确认的精确时刻时，不用固定回合时长或虚构分钟补齐。

完整示例补充了真实的 `world_state.calendar` 标签。升级沿用现有预设迁移流程：先完整备份旧预设，替换内置条目，保留独立的自定义补充条目及启用状态。
