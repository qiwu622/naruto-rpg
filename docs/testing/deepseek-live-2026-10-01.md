# DeepSeek Flash 专用适配实测

日期：2026-10-01。使用用户授权的官方账户；模型固定 `deepseek-flash`。11 个测试场景、12 次真实请求全部通过，HTTP 均为 200，输出没有被测试上限截断。未使用玩家存档、未保存 Key、未发布网站或安卓包。

## 对照结果

使用相同的合成 28 轮历史、固定规则和当前任务。每次改变本轮事实和输入；普通模式保持原请求构造，专用模式把项目动态上下文放在历史后，并显式关闭思考。正文要求 120–180 字，仅用于控制本次测试，不修改产品篇幅设置。

| 指标，三次请求合计 | 普通模式 | DeepSeek 专用模式 |
| --- | ---: | ---: |
| 输入 token | 10,626 | 10,551 |
| 缓存命中 token | 0 | 6,400 |
| 输出 token（已包含思考） | 979 | 362 |
| 思考 token | 620 | 已关闭，供应商未返回该字段 |
| 正文平均字符数 | 160 | 162 |
| 高峰价估算费用 | ¥0.029084 | ¥0.011454 |

专用模式首次请求为冷缓存；第 2、3 次均命中 3200 / 3517 输入 token（约 91%）。三次固定前缀的 SHA-256 相同，当前事实仍逐次更新。三次合计估算费用下降约 61%，同时来自缓存和关闭思考；这是小样本结果，不能承诺其他预设、历史窗口或游戏阶段有相同比例。

普通模式三次请求的 `messages` 均与旧规范化函数结果逐字节一致，未增加 `thinking` / `reasoning_effort`。只打开专用模式才改变上下文排列及思考参数。

## 额外场景

- 流式正文：连续收到多段正文，用量事件只报告一次，命中 3200 token。
- 低思考 JSON：饭团从 2 减为 1，金钱保持 100，未选择购买的起爆符为 0。
- 正文预填充：官方接口正常接受末尾 assistant 内容并返回完整正文。
- 项目默认变量预设：真实输出通过游戏变量校验器，生成饭团减 1 的结构指令和记忆；没有把购买起爆符写成已发生事实。
- SDK 原生工具：实际执行一次只读查询、两次模型请求，返回正确数量；第二步保留第一步的 `reasoning_content`，两步各报告一次用量。

## 费用与测试边界

按[官方人民币价格](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/)的高峰单价保守核算：每百万 token 命中输入 0.04 元、未命中输入 2 元、输出 8 元。12 次请求完整返回 usage，合计估算 **0.06473512 元**；若适用空闲价则更低。输出费用已包含思考，命中 token 没有重复计入未命中费用。

余额接口在本次测试前后差额为 0；可能存在账单入账延迟，因此不把估算写成实扣，也不据此声称免费。预算保护对每次请求按全部输入未命中及最大输出预留费用，累计预留 **0.805632 元**，总上限 2 元；最多 16 次请求，实际仅 12 次。错误和结果未知的请求不释放额度。没有自动重发付费请求。

调用经过项目真实 AIClient 和 SDK 的请求构造、响应解析与用量统计。SDK 的本地代理传输在测试中直接转发到官方接口，未验证线上服务器代理。没有在安卓实机发起此次付费测试；此前安卓共享适配、设置 UI 与代理分支由离线回归覆盖。合成短任务不代表长篇生成、多小时游戏或所有第三方中转站均已验证。
